# 学科 Hub · 架构设想

本文是**产品口径**。题型、角色、题库磁盘格式改了先改这里。函数在哪个文件、请求怎么走，见 [技术架构](tech.md)（改代码时维护那篇）。

## 要解决什么

家里局域网的全科答题站：学生点按钮作答，家长点按钮看进度、组卷、加题。评测跑在 Ubuntu 上，浏览器打开即可。

真源是**带标签的题库**，不是事先写死的整卷。学生有两条路：单题闯关、按标签抽出的试卷。阅读/材料题点进去后左栏材料、右栏答题。数理过程可拍照。双方都不填 YAML、slug、LaTeX。

不要做成第二份 Leet Hub。编程评测仍在 [leet-hub](https://github.com/ZhiqiangBao/leet-hub)。

## 和 Leet Hub 的关系

| | Leet Hub | 学科 Hub |
| --- | --- | --- |
| 学生交什么 | 函数代码 | 选项、填空、数值、短答、作文、演算纸照片 |
| 对错 | 隐藏测例跑程序 | 客观题本地对答案；主观题才走细则 + 大模型 |
| 页面 | 一题一页，左右编辑器 | 闯关或试卷；材料题左右分栏 |
| 语言下拉 | Python / C / C++ | 无 |
| `tests.jsonl` | 要 | **不要** |
| starter | 要 | 无 |

运维同构：Ubuntu + systemd + `git pull`，`data/` 里账号、成绩、本地题、作答图片不进 Git。服务名 `subject-hub`。答题端口 **8090**；家长在主机本机 **8091** 注册管理员，可注册多位。

## 操作原则

学生只做：点进去、作答、提交本题。家长只做：点选条件、确认、改对了没。

- 输入只收普通中文/数字、选项点击、拍照。不要提示填 YAML / LaTeX / slug。
- 科目、年级、难度、题型用按钮或卡片。
- 草稿自动保存。学生只看到「提交本题」或「交卷」。
- 客观题提交后自动出分；主观题自动排队给模型；导入成功的题自动进闯关池。
- 学生年级可空；闯关筛选不点年级就等于各年级都抽。家长也可在管理页给学生补年级。
- 外部导入可选 YAML/ZIP 文件，或粘贴聊天回复；服务器先解析并给预览，管理员确认后才保存。单次输入不超过 2 MB、最多 100 题，ZIP 展开后也不超过 2 MB；题目编号重复时拒绝导入，不覆盖现有题。
- 「重新读取本机题库」只重读当前主机的 `bank/` 和 `data/local-bank/`；不会联网拉取仓库更新。

SSH、Git、模型 URL 只给装机的人。8090 是未加密 HTTP，仅用于可信局域网，不应转发到公网；8091 默认只绑定 `127.0.0.1`，只用于在主机本机注册管理员。管理员登录后通过 8090 使用受登录保护的管理功能。

## 角色

管理员（家长或老师）看多位学生的成绩、在测验里改判匿名答卷、组卷、加题、管班级和分组。在评测机后台端口（默认 `127.0.0.1:8091`）注册，**可以有多位**。答题网页（8090）上的注册永远是普通学生，不需要管理员同意，也绝不会因为「第一个注册」就变成管理员。

班级**一定是**分组，分组**不一定是**班级：可以在班里再分小队，也可以建跨班的组。一个学生可以同时在多个分组里。发布测验时选择分组作为对象，其它分组看不见试卷；对象分组里没作答的人，截止后仍计入成绩（缺考 0 分）。

学生**登录名**就是注册时填的名字，注册后不能改（老师也不能改），学生自己的页面只显示登录名。**真名**默认等于登录名，只有老师能改、加在档案里，学生本人页面看不到。

| 角色 | 日常 | 不需要会 |
| --- | --- | --- |
| 学生 | 登录、点科目闯关或打开试卷、作答、看自己的成绩 | 命令行、Git、API、YAML |
| 管理员 | 学生页看成绩；测验里匿名改判主观题；点选组卷、导入/白话加题；学生账号里建分组、代开、改真名 | 同上 |
| 装机的人 | Ubuntu、配模型入口、Git 推送 | 学生端用不到 |

双系统安装见 [dual-boot-grub-iso.md](dual-boot-grub-iso.md)，不要放进给学生看的说明。

## 科目与标签

科目 id：`chinese` `english` `math` `physics` `chemistry` `biology` `history` `politics`

每题恰好一个：`subject`、`grade`（1–12）、`difficulty`（`easy` | `medium` | `hard`）、`type`。知识点 `tags` 可多个，一题可同时挂多个（与 leet-hub 相同）。筛选和组卷都取交集。

## 题型

| type | 学生动作 | 怎么判 |
| --- | --- | --- |
| `single` | 点一个选项 | 与标准选项比 |
| `multiple` | 点多个选项 | 默认全对才满分 |
| `blank` | 填文字 / 点符号 | 同一个空可列多种可接受写法；统一全角字符、常见符号与规范上下标，保留大小写和英文词间空格。数学、物理、化学的纯数值表达式可按精确有理数比较。公式用括号标明范围；**答案里不要 LaTeX** |
| `numeric` | 填数值，也可写分数或百分数 | 标准值 + 容差；`0.5`、`1/2`、`50%` 可按相同数值判分；可选单位 |
| `short` | 写短答 | 细则 + 大模型，可改判 |
| `essay` | 写作文 | 同上 |
| `passage` | 左材料、右多框 | 各框按自己的 type 判；整篇算闯关一题 |
| `steps` | 过程文字和/或拍演算纸，可选终值 | 终值本地判；过程送模型（有图则送图） |

不做：`expression` 符号等价、听力、完整公式编辑器、页内手写识别。

## 填空公式：括号标明管到哪里

公式插入栏只给**数学、物理、化学、生物**。语文、英语、历史、政治的填空是普通输入框，不出现根号积分。

学生填空和教师候选答案输入框关闭自动大写、自动纠词，避免手机改写答案；作答按输入原文保存，判分时再规范常见等价写法。英文词中的直/弯撇号可对齐，但不会把 `dont` 当作 `don't`，也不会把 `it’s` 当作 `its`。

学生不写 LaTeX。根号、积分、分数、上标都靠**圆括号**标明作用范围。按钮插入时自带括号（`√()`、`∫()dx`），光标在括号里。出题 `answer`、学生作答、本机判分用同一套字符。

| 结构 | 必须怎么写 | 对 | 错（范围不清） |
| --- | --- | --- | --- |
| 根号 | `√` 后面立刻一对圆括号，括号里才是根号内容。单个字母/数字也要括号。 | `√(2)` `√(2+1)` `√(2)+1` `2√(x)` | `√2` `√2+1` `√2x` |
| 积分 | 先 `∫`，有上下限则 `_下限^上限`（下限上限不是单个符号时也加括号），然后一对圆括号包住**被积式**，最后 `d`+变量。 | `∫(x)dx` `∫(x+1)dx` `∫_0^1(x^2)dx` `∫_(0)^(n+1)(x)dx` | `∫x+1 dx` `∫x^2dx`（平方算不算进积分） |
| 分数 | 分子或分母里有加减乘除、根号、积分时，那一侧加括号。单个数字/字母可以不加。 | `1/2` `x/2` `(a+b)/c` `1/(x+1)` `(1)/(2)` | `a+b/c`（到底是不是 `(a+b)/c`） |
| 上标 | 指数不是单个数字时用 `^(…)`。 | `x^2` `x²` `2^(n+1)` | `2^n+1`（到底是 `2^(n+1)` 还是 `(2^n)+1`） |
| 求和 | 与积分相同：管到的项用括号。 | `∑_(i=1)^n(i^2)` | `∑i^2` |

判分先做保守的写法规范化，例如 `x²`、`x^2`、`x^(2)` 对齐，`H₂O` 与 `H2O` 对齐；`H²O` 与 `H₂O`、`Co` 与 `CO` 仍不同。数学、物理、化学中 `1/2` 与 `0.5` 这类纯数值表达式可按精确有理数比较，英文填空保留词间空格。不推断「没写括号时根号管到哪」，也不做任意代数恒等式判定；复杂等价答案列出候选，或改用 `short`。出题和学生都应把括号写全。题干公式仍可用 `$...$` 渲染；`$` 只出现在题干，不出现在填空 `answer`。

## 题库磁盘格式

两层，互不改对方的文件：

1. `bank/`：跟仓库走。`git pull` / 「更新题库」只动这里，用来发新题、修仓库里还没人改过的题。
2. `data/local-bank/`：只在这台主机。网页上保存、粘贴入库、白话加题都写到这里。`data/` 已在 `.gitignore`，更新脚本也不碰它。

加载顺序：先读 `bank/`，再读 `data/local-bank/`，**同名 slug 以本机为准**。所以管理员改过的题，仓库里即使后来改了同一题，这台机仍用本机那份；仓库新增的其它题照常出现。

不要在评测机上手改 `bank/` 里的文件：那一改，下次 `git pull` 会被盖掉。要改题，走管理页，让它落到 `data/local-bank/`。

若希望某题重新跟仓库走：删掉 `data/local-bank/` 里对应的 yaml 再更新题库（现在网页还没有「撤销本机修改」按钮）。

独立一题：

```text
bank/<slug>/
  meta.yaml
  stem.md
```

材料题：

```text
bank/<slug>/
  meta.yaml          # type: passage
  passage.md
  parts/01.yaml
  parts/02.yaml
```

过程题 `type: steps`：题干在 `stem.md`；`allow_photo` 默认 true；终值用 `numeric` 子框，过程用主观框 + 细则。

也可落成单个 YAML（导入用）。不要把整卷当题库文件。

出题说明见 [出题说明](author-bank-skill.md)。给**任何能聊天的人工智能**看（不限定某一家）。家长在网站点「复制出题说明」，贴进聊天页即可。说明写得足够直白，常见、普及的模型也能按模板吐出可入库文件。

网站也可直接调用模型：管理员在「模型」页统一配置出题与判题接口，在「加题」页按年级、科目、知识点生成题目。后端检索本地课标原文并附上 PDF 页码，校验生成结果后只提供预览；管理员检查、修改后逐题入库。入库后与其他题目一起用于组卷和闯关。图片录题属于后续范围。

## 两种学生模式

**闯关**：点选科目 / 年级 / 难度 / 知识点（不点的那一项等于全部），从题库随机抽约 20 题。材料题整篇算 1 题。抽题写入本次 run，刷新不换题。答一题判一题，已交不可改。结束看总分。未完成时可以接着上次，也可以按新标签重开。

答题内容会自动保存到服务端；若网络保存失败，浏览器会按登录账号、闯关/试卷和当前题目把文字作答暂存到这台设备。返回同一账号、同一题后可以选择恢复；切设备、清理站点数据或无法使用浏览器本地存储时，不能靠这份本地备份恢复。离开答题页会尝试先保存；离开前应确认页面显示已保存。若网络同步失败，使用页面的重试或恢复草稿入口；浏览器被强制关闭或离线时仍可能有未同步内容。

**试卷**：老师组卷（此时学生还看不见）→ 发布时选择分组（班级或班内/其它分组）、填写答题起止时间（默认北京时间，顶栏下拉可改时区；开考以主机时钟为准；也可按分组错开） → 只有对象分组里的学生能看见试卷卡片，开始之前点不进去、看不到题目 → 窗口内自动保存、题号卡跳转；单选题选完跳下一题，其它题点「下一题」；未全部保存不能主动交卷，截止才强制收卷 → 交卷只收答案，**全部对象截止后**老师才能点「开始评分」才机评；对象分组里没作答的记缺考 0 分 → 老师只在「测验」的匿名答卷里改主观分（模型分只作参考，不覆盖已手改）→ 本机和模型分都出齐才能「发布成绩」→ 发布后学生才看见分数，管理员从「学生」点进该生这一次才能看作答（不会跳进测验）。组卷是标签抽样，不是按对错改难度。

发布时会把题目内容冻结到该试卷。之后改题不影响已发布试卷，只影响后续组卷。升级时为旧版已发布试卷补快照是尽力恢复：以当时可读到的题库补回，缺失题目或小问编号/分值与历史作答记录冲突时，将该题标为不可还原并保留原分数，不猜原题内容。若旧题的题干或答案曾变更、但题目编号及结构仍相同，系统无法从旧库辨别历史文本；此类旧卷快照不保证能还原原始版本。

## 答题页

桌面：左栏材料或题干，右栏答题框。手机：上材料、下答题。输入即保存。试卷有题号卡。步骤题优先「拍演算纸」。

## 判分

```text
闯关「提交本题」（立刻判）/ 试卷老师「开始评分」（须已截止）
  ├─ 客观框：主机比对 → 写入机评分（不调模型）
  └─ 主观框：待评分 → 通用 HTTP
        → 写入机评分与评语；管理员手改写入另一套分
        → 模型再评只更新机评分，不覆盖已手改
```

终值、选择、填空不送给模型。模型挂了客观题仍出分。密钥只在主机。细节见 [llm-grading.md](llm-grading.md)。

## 部署

1. 评测主机 Ubuntu：网页、账号、成绩、调模型。监听 `0.0.0.0:8090`。
2. 维护：Windows / WSL 改仓库后推送；主机 `./scripts/update-from-github.sh`。
3. 答题端：浏览器。不配 API 密钥。

作答、本地题、图片只在 `data/`。可执行包装、wheel、Windows 当主机等见 [远景规划](vision.md)，现在不改装机路径。
