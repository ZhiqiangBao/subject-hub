# 当前功能与维护约定

本文按当前源码记录已实现的产品行为、维护边界和后续验证方式。技术细节以 [技术架构](tech.md) 为准；安装、升级和数据恢复步骤见 [评测主机](host.md)。

## 当前已实现

| 范围 | 当前行为 |
| --- | --- |
| 学生与管理员 | 学生在 8090 自助注册；管理员只在主机本机 8091 注册，然后在 8090 登录管理。老师按授权科目查看和评分，家长可管理全科。 |
| 题库 | 仓库题和 `data/local-bank/` 本机题合并读取；同 slug 本机版本优先。管理员可改题、用 AI 生成并预览，或导入 YAML/ZIP。 |
| 闯关与试卷 | 客观题本机判；主观题逐问排入持久评分任务。试卷按分组发布、到期收卷，截止后由老师开始评分；学生只在成绩发布后查看分数和答卷。 |
| 试卷题目版本 | 发布时冻结题目内容；此后改题不影响已发布卷。旧卷升级迁移按下文所述尽力恢复。 |
| 作答草稿 | 输入自动保存到服务端；网络保存失败时，浏览器按账号和作答上下文保留文字草稿，回到同一账号和题目时可选择恢复。 |
| 主机更新 | Ubuntu 更新脚本先隔离构建并运行检查，再停服、备份并校验数据，之后切换版本并检查健康接口。 |

学生始终使用主机的 `http://<主机局域网IP>:8090`；不按学生单独开端口。

## 主观题评分、人工改判与重试

模型按一个主观作答框评分。客观题和过程题终值都在主机规则判分。学生闯关提交时排队；试卷交卷只收答案，老师须等所有对象截止后开始评分。模型未配置时任务保留在队列中，接入模型后继续处理。

评分任务记录在 SQLite `grade_jobs` 表，与作答提交放在同一事务中；保存题目、作答、照片引用和评分前状态，防止旧任务在新作答或人工改判后写回。进程重启后队列仍可恢复。管理员可查看匿名状态；未开始或已发布成绩的试卷不允许重评。

管理员可以在允许评分的阶段明确要求对已人工评分的主观题再次调用模型。该操作只更新模型参考分和模型评语，人工分始终是最终分。普通「重试未评」和批量重试会跳过已有人工分的题。客观题不能模型重评。模型返回结构、分项、分数范围和合计任一项不合规时，任务失败并保留待处理状态；不会把超限值截断后当成正式分。

照片评分一次发送该问的所有照片，每问最多 3 张，每张最多 6 MB，支持 JPEG、PNG、WebP。图片无法读取或模型不接受图片时，任务失败，不会自动移除图片改成纯文字评分；应由管理员人工处理。

模型配置在主机 `data/llm.env`；同名环境变量优先。若启动环境设置了模型地址或模型名，网页设置不能覆盖，应由装机人改启动配置。出题和评分共用该接口。密钥不回传网页；完整配置行为见 [大模型评分](llm-grading.md)。

## 题目导入与本机题库

外部题目先粘贴或选 YAML/ZIP 文件，再查看服务器生成的预览，最后明确确认入库。单次输入最多 2 MB、最多 100 道题；ZIP 展开后总量也不能超过 2 MB。当前题库或同一批次中已有相同 slug 时拒绝整批导入，不覆盖题目。教师只能导入自己有权限的科目。

网页「重新读取本机题库」只重新扫描当前机器上的 `bank/` 与 `data/local-bank/`，不联网、不执行 Git 更新。需获取 GitHub 新版本时，在主机仓库运行 [升级脚本](host.md#从-github-更新)。

## 迁移限制与作答恢复

新发布试卷保存题目快照；编辑题库不会改变已经发布的试卷，新组卷会使用新题目。

升级旧版已发布试卷时，程序只能用升级时可读到的题库做一次尽力恢复。题目缺失，或历史作答中的小问编号/分值与现行题库矛盾时，该题标为不可还原，已有答案与分数保留，不推测原题。若同 slug 题目的文字或答案变过、但小问编号和分值仍相同，旧库没有足够证据识别差异，因此无法保证恢复的是当年的题面。升级前备份仍是保留旧数据的依据。

答题页离开前会尝试同步草稿；若失败，页面保留本地备份并提示重试或恢复。该备份只在同一浏览器、设备、登录账号和作答上下文可用，不能跨设备同步，也不包含尚未上传的照片。若浏览器本地存储被清理或不可用，离线期间的新文字作答可能无法恢复。

## 网络、数据与恢复

8090 使用未加密 HTTP，仅面向可信家庭或学校局域网；不要做公网端口映射。8091 默认仅监听 `127.0.0.1`，只用于在主机本机注册管理员。使用模型时，题干、评分细则、该生该问作答和照片会发往管理员配置的模型服务；不要假设远端服务与本机具有相同的数据保护边界。

数据库、账号、成绩、本机题目、照片、LLM 配置、会话签名文件都在服务实际使用的 `data/` 目录。备份含 API 密钥和学生数据，应受限保存。先停止所有写入进程再用 `scripts/backup_restore.py backup`；用 `verify` 检查备份；`restore` 只恢复到备份之外、尚不存在的新目录，不会覆盖当前数据。命令和回退流程见 [评测主机](host.md)。

若旧版 8090 曾被不受信任设备访问，可按需轮换会话签名密钥：先停服、备份并验证实际数据目录，再替换启动环境中的 `SUBJECT_HUB_SECRET`，或以服务账号在默认仓库内 `data/`（或实际数据目录）生成新的 `secret.txt`。轮换会令旧会话失效；如怀疑模型密钥也暴露，应在模型服务提供方轮换。此为预防措施，不代表已发生泄露。具体步骤见 [评测主机](host.md)。

## 更新检查

```bash
./scripts/update-from-github.sh
```

升级脚本要求 Python 3.10+，并要求 Node.js 22.22.2+（22 系列）、24.15+（24 系列）或 26+。脚本在版本切换前运行 Python 单元测试、前端类型检查、前端测试和构建；失败时不切换正在运行的版本。切换后启动/健康检查失败会停服并给出备份及旧版目录，按输出路径运行 `./scripts/rollback-ubuntu.sh '旧版目录'`。

固定的 Python 直接依赖当前只在 Windows、Python 3.13.6 环境验证；Ubuntu 实机验证仍需由 CI 或部署维护流程补齐。开发者也可在隔离测试目录中运行：

```bash
python3 -m unittest discover -s tests
cd frontend
npm ci
npm run typecheck
npm test
npm run build
```

上述测试不得指向正在使用的生产 `data/`。升级脚本会在临时 staging 目录中使用隔离的测试数据和题库。

## 仍不做

- 用模型判选择、填空、数值和过程题终值。
- 让学生或管理员在答题网页填写 YAML、slug、LaTeX 或 API 密钥。
- 每名学生单独端口、摄像头防作弊、听力、公式 OCR。
- 与 leet-hub 共用成绩库或改造 leet-hub 页面。
- 公网 SaaS、手机当评测主机、需要签名的 Windows 安装器或应用商店分发。
