# 学科 Hub · 下一阶段计划

本文接当前代码和已确认口径。实现时先改本文和 [架构设想](architecture.md)，再改代码。不要改 `.cursor/plans/` 里的旧稿。

## 先回答两个问题

### 1. 大模型按小题评分——已经实现，不是后置

主机用通用 HTTP（OpenAI 兼容的 `/chat/completions`）评**一个主观框**，不是整张卷。

流程：

1. 学生提交该框（闯关是「提交本题」；试卷是交卷时对该卷每题调用一次提交）。
2. 客观框（选择、填空、数值、过程题终值）只在本机对答案，**不进模型**。
3. 主观框（简答、作文、材料题里的简答、过程题的步骤）记成「待评分」，丢进后台队列。
4. 队列每次只带：**这一问的题干、本问细则 `rubric`、参考答案、该生这一问的文字**；材料题附上**本题**的阅读材料（左栏），不附带同卷其它题、也不附带别人的作答。
5. 有演算纸则带图（对端不认图则退回纯文字并注明「图片未评」）。
6. 模型必须返回分项 JSON；主机校验每项不超过细则满分、`total` 等于分项之和，通过后写入**该生这一问**的 `score` / 评语。
7. 管理员可改判；已改判的不覆盖，除非点「用模型再评一次」。

要真正跑起来，评测机必须配置：

```text
SUBJECT_HUB_LLM_BASE_URL
SUBJECT_HUB_LLM_MODEL
SUBJECT_HUB_LLM_API_KEY    # 内网无鉴权可空
```

未配置时：客观题照常出分，主观题停在待评分，等人手打。文档曾写也可放 `data/` 本地文件，**代码目前只读环境变量**，这一点要补。

已知缺口（修，不是重做）：进程重启后内存队列丢失（库里仍是待评分，管理页可点再评）；试卷考试模式交卷前不逐题送模型（按设计，交卷后才送）。

### 2. 限时测验的主观题 AI 评判——可以，而且应复用现成队列

限时只决定「何时截止、能否再改」。截止后走现在的交卷：`submit_item` → 主观框入队 → 写回该生该题。

不需要为限时另写一套模型调用。注意：

- 到点以**服务器时间**交卷，倒计时只是给学生看。
- 交卷后客观立刻出分；主观可能过几秒到几分钟才从待评分变成已评分，管理卡片上显示「待评 n」。
- 学校一场多人交卷会排队，可接受；不要同步阻塞交卷接口。
- 改判权限仍按管理员科目走（见下）。

## 目标产品路径

**学生（8090）**

1. 中文名注册/登录。
2. 闯关；或打开管理员发来的试卷（作业不限时，考试限时，倒计时可见）。
3. 「我的成绩」：闯关/试卷 + 按标签（知识点可多选，条件取交集）。
4. 词汇场可看本次排名（第几 / 共几人）。

**管理员（8091 注册，8090 登录管理）**

1. 注册时：家长点「全科」；老师点一个或多个科目。
2. 首页：**用户卡片**（中文名 + 其可见科目的成绩概览）→ 点进该生成绩详情和**单次测验卡片** → 点进该次每一问；主观题有改判和「用模型再评」。
3. 另有 **测验卡片** 列表：随机组卷（可限时）后自动出现一张「本次测验」→ 点进去是参加学生卡片 → 再点进作答/改判。
4. 老师只看见本学科标签下的成绩、作答、改判；家长看见全科。

## 标签口径（筛选与组卷都遵守）

- 每题恰好一个：科目、年级、难度、题型。
- 知识点 `tags` 可多个，一题可同时挂多个（与 leet-hub 相同）。
- 筛选取**交集**：已选条件必须同时满足；知识点多选时题目必须带上所选的每一个知识点。

## 下一件要做 · 管理员改题 — 代码已接

管理页「题库」：按标签筛选（科目/年级/难度/题型单选，知识点多选取交集）→ 点进一题改题干/材料、选择题按钮点答案、填空每种正确写法一个按钮、主观题改参考和细则 → 保存写入 `data/local-bank/`。Git 更新不覆盖本机改过的题。

## 分步实现

### 第 1 步 · 收口已有管理流（先做）— 进行中 / 代码已接

- 中文用户名：最长 32 字，登录名即显示名。
- 管理首页用户卡片；测验卡片列表；点学生看单次测验卡片；点测验看参加学生和排名。
- 知识点多选取交集；科目等单选。
- 配了模型则交卷后主观分自动回写。

### 第 2 步 · 家庭 / 学校权限 — 代码已接

- 8091 注册：全科或若干科目。接口按科目过滤。

### 第 3 步 · 限时测验 — 代码已接

- 组卷可选 20/40/60 分钟；到点服务器强制交卷；空主观题 0 分。

### 第 4 步 · 单词测验排名 — 代码已接

- 每场试卷按总分排队；待评不进正式名次。

### 第 5 步 · 模型运维 — 代码已接

- `data/llm.env`；启动时重试待评；管理页「重试未评」。

### 第 6 步 · 管理员改题 — 代码已接

- 管理「题库」按标签列表；点进去改题干、选择/填空/细则；保存到 `data/local-bank/`。

## 远景（现在不要做）

Windows 主机若做，对照 **Hermes Agent**：脚本装运行时 + 本机后端 + 浏览器当 GUI（不做 Electron 壳、不办签名）。手机只当客户端（以后可套 WebView / 主机下发 APK），不当服务机。详见 [远景规划](vision.md)。正式装机仍是 Ubuntu。不要为这些改当前 `setup-ubuntu.sh`。

## 明确仍不做

- 用模型判选择、填空、终值。
- 学生或管理员填 YAML / slug / LaTeX。
- 每学生独立端口、摄像头防作弊、听力、公式 OCR。
- 改 leet-hub、两套成绩库合并。

## 验收（做完第 1–4 步应对得上）

- 配好模型后：学生交一问简答，该生该题从待评分变为数字分，管理员打开的是这一问而不是整卷。
- 限时卷到点后不能再写；主观题随后出 AI 分，管理员仍能改判。
- 家长看见全科卡片；只注册了英语的老师看不见数学测验和数学改判。
- 用户卡片 → 测验卡片 → 作答/改判；测验卡片 → 参加学生 → 作答/改判。
- 词汇场有排名。
- 中文名可注册、可显示。
