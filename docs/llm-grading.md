# 模型配置与主观题评分

**判分时，大模型只判断主观题。** `single` / `multiple` / `blank` / `numeric` 全部在主机用规则比对，判分请求不经过模型。计算题的**终值**同样只走本地规则。

网站「加题」中的 **AI 出题** 也使用这套接口。出题与判题统一在管理员「模型」页管理地址、密钥、模型及思考设置；保存一次，两处共用。出题时后端按年级、科目从 `docs/standards/` 读取相关课标原文页，生成题干、答案与评分细则，校验后提供预览。管理员可修改并逐题确认入库，生成请求本身不保存题目。操作入口和格式见 [出题说明](author-bank-skill.md)。

主观题（`short` / `essay`、材料题里的简答框、过程题的步骤框）不跑测例。主机拿题面、参考答案、评分细则、学生作答（可带演算纸图片）调用配置好的 HTTP 接口，收回分数和评语。

## 通用接口

评测主机上只保留一层很薄的客户端：给定根地址、密钥、模型名，发一段对话，拿回文本。不写死厂商。

配置保存在主机的 `data/llm.env`（不进 Git）；同名环境变量优先。管理员登录后也可在网页「模型」页填写，默认本机 `http://127.0.0.1:8080/v1`。若启动环境已设置模型地址或模型名，网页不能覆盖这些启动配置，应由装机人修改后重启。API 密钥不会回传到网页；管理员页通过 8090 HTTP 保存配置，因此只应在可信局域网使用。

```text
SUBJECT_HUB_LLM_BASE_URL     # 服务根地址，例如 https://host.example/v1
SUBJECT_HUB_LLM_API_KEY      # 可选；内网无鉴权的服务可留空
SUBJECT_HUB_LLM_MODEL        # 模型名，原样传给对端
SUBJECT_HUB_LLM_CHAT_PATH    # 可选；默认 /chat/completions
SUBJECT_HUB_LLM_ENABLE_THINKING    # 0 关掉思考（默认）；1 打开
SUBJECT_HUB_LLM_REASONING_EFFORT   # none / minimal / low / medium / high / xhigh；关掉时固定 none
```

思考默认关掉，加快主观题评分。请求按兼容顺序带这些字段（对端不认就自动去掉再试）：

- OpenAI Chat Completions 标准：`reasoning_effort`。关掉用 `none`，调低用 `low`。GPT-5 早期只有 `minimal`，o 系列没有 `none` 时用 `low`。
- 阿里百炼 / 通义 Qwen3+：HTTP JSON 顶层 `enable_thinking: false`（Python SDK 才进 `extra_body`）。
- 本机 vLLM / llama.cpp：`chat_template_kwargs.enable_thinking`。

请求约定：

- 方法 `POST`，JSON 正文。
- 带 `messages`（角色 + 内容）和 `model`。
- 鉴权用 `Authorization: Bearer <key>`（无密钥则不加这头）。
- 从返回 JSON 里取助手文本（常见字段 `choices[0].message.content`）。
- 有演算纸时，用户消息用多模态内容列表（本问文字 + 所有照片）。每问最多保留 3 张 JPEG/PNG/WebP，每张不超过 6 MB。照片无法读取、接口不接受图像或评分响应无效时，这次任务失败并留待处理；**不会自动去掉图片、退回纯文字评分**。含图失败请人工评分，不能把“图片未评”当作已完成的完整评分。

原则：

- 学生端没有「填 API Key」的页面。密钥留在主机配置中；出题或评分请求会发往配置的模型服务，请只使用你信任的端点。
- 未配置入口时：主观题保持待评分，家长手打；客观题不受影响。
- 超时、限流、非 JSON、校验失败都算这次评分失败，保留待评状态。分项 ID、分数范围、分项合计或总分校验失败时不会把错误分数截断成正式分，可由管理员重试或人工处理。

## 评分细则

细则写在主观题文件里。客观题没有 `rubric`。

```yaml
type: short
points: 8
reference: |
  指出作者用对比突出主旨，并引用一处原文。
rubric:
  - id: point
    points: 4
    require: 准确概括主旨或对比手法
  - id: evidence
    points: 3
    require: 有具体引文或可定位的段落，不能只空喊
  - id: language
    points: 1
    require: 语句通顺；错别字过多则本项 0
```

过程题的细则按步骤要点给分，不要把终值交给模型。

## 送进模型的内容

每次只评**一个框**：

1. 科目与题型（仅主观）
2. 题面（材料题附上阅读材料；过程题附上题干）
3. 参考答案
4. 细则列表
5. 该框学生作答全文
6. 若有演算纸：该问的全部图片

不要附带同题终值以外的其它客观答案。不要附带其他学生的作答。

要求模型返回可解析结构：

```json
{
  "items": [
    { "id": "point", "score": 3, "reason": "主旨对，未点出对比" }
  ],
  "total": 3,
  "comment": "……"
}
```

`total` 必须等于分项之和，且每项不超过该条满分。主机再做一次算术校验，对不上则评分失败并转人工。

禁止把系统提示里的密钥说明写进学生可见评语。

## 和家长改判的关系

自动分是初评，写在机评分字段。管理员手改写在另一套字段，作为最终分。

在允许评分的阶段，管理员可以明确要求对已手改的主观题重新调用模型。重评只更新模型参考分和模型评语，人工分仍是最终分，不会被覆盖。普通「重试未评」和保存模型配置时的批量重试会跳过已有人工分的题；成绩发布后不能再重评。

评分任务保存在 SQLite 的 `grade_jobs` 中，不依赖只存在内存里的队列；服务重启后会继续处理已排队任务。任务与当次作答、题目内容和评分前分数状态绑定，旧任务不会覆盖之后的修改。模型未配置时任务可以排队等待；失败任务会标记为待处理，由管理员按单题或批量重试。管理员可查看匿名任务状态，不显示学生姓名。

## 科目上怎么用

| 科目 | 走模型 | 不走模型 |
| --- | --- | --- |
| 语文 | 阅读短答、作文 | 默写、选择 |
| 英语 | 作文、翻译 | 单词填空、选择 |
| 数学 | 过程、证明（可带演算纸） | 计算终值、填空、选择 |
| 物理化学生物 | 过程、实验简述（可带演算纸） | 选择、数值、化学式填空 |
| 历史政治 | 材料简答、辨析 | 选择、填空 |

## 第一期范围

必须有：通用 HTTP 入口、细则只存在主观框上、结构化输出校验、失败可重评、家长改判、演算纸走多模态。

后置：多模型对比、听力口语。
